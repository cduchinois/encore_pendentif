# Encore — project context

Encore is a pendant that captures a party's setlist in real time, fully on-device, and gives the wearer back their night: timestamped setlist, transitions, highlight moments, and a ready playlist. Built in 1 day at the Gemma 4 Hackathon Paris (2026-07-25). Team: Jade (iOS + firmware), Mathieu (pipeline + data).

Full PRD: `docs/PROPOSAL.md`. Day plan: `PLAN.md`. Demo: `demo/demo_script.md`.

## Architecture

```
[Pendant: XIAO ESP32-S3 Sense]
  mic PDM -> audio frames --WiFi/UDP (BLE fallback)--> [iPhone app]
  touch: double tap = PIN, long press = PRIVACY        |
  WS2812B LED <-- CMD_LED (ambiance color / pin flash) |
                                                       v
[iPhone (all local)]                          [Mac (prep + fallback)]
  1. ShazamKit custom catalog (offline match)   pipeline/ = same logic in Python
  2. embeddings similarity                      data prep runs the night before
  3. ShazamKit world catalog (if online)
  4. Gemma 4 E2B ID card (native audio in)
  journal -> recap -> MusicKit playlist
                                     [deferred, online only]
                                       SerpAPI lyrics/tracklist resolve
                                       iTunes/Spotify enrichment
```

## Module map

- `firmware/` — PlatformIO, C++. Capture + stream + touch + LED. Owner: firmware-dev agent.
- `ios/` — Swift app (create the Xcode project locally; see ios/README.md). Owner: ios-dev agent.
- `pipeline/` — Python. Catalog prep (fingerprints, enrichment), SerpAPI resolver, context compiler, benchmark. Owner: pipeline-dev agent.
- `contracts/` — shared schemas and the pendant protocol. **Source of truth between modules.**
- `data/` — gitignored payloads (catalog index, audio). Manifests and audit notes are committed.
- `demo/` — demo script, test plan, backup HTML dashboard.

## The contracts rule (non-negotiable)

Never change a message format or JSON shape directly in code. Change the file in `contracts/` first, then update every consumer (Swift AND Python) in the same branch. The verifier agent checks this.

## Repo rules

- Trunk-based. Branches `feat/<issue#>-short-name`, merged small and often. `closes #N` in the PR.
- Commit prefix by module: `ios:`, `fw:`, `pipe:`, `data:`, `docs:`.
- Merge to main only with green tests (`pipeline: pytest`, `ios: xcodebuild test`, golden clips when they exist).
- **15:00 freeze on demo day**: after freeze, main accepts demo fixes only. Bonuses stay on branches.
- Work items live in GitHub issues (run `./bootstrap.sh` once after creating the repo). No parallel todo files.
- Decisions get one line each in `DECISIONS.md` (what + why), written when they happen.

## Env rules

- Secrets NEVER in git: SerpAPI key, Spotify client id/secret, AudD key. They live in `.env` (gitignored). `.env.example` lists the names.
- If a key ever lands in a commit, rotate it immediately; do not just delete the line.

## Commands

- Pipeline setup: `cd pipeline && pip install -r requirements.txt`
- Catalog fingerprint (Mathieu, overnight): `python pipeline/ingest/fingerprint_catalog.py --music-dir <dir>`
- Enrichment: `python pipeline/ingest/enrich_catalog.py --priority data/demo_set/demo_tracks.txt`
- Pipeline tests: `cd pipeline && pytest`
- Firmware build/flash: `cd firmware && pio run -t upload` (XIAO ESP32-S3 plugged in)
- Context benchmark: `python pipeline/bench/context_bench.py`

## What NOT to touch

- `hardware/3dprint/*.stl` are generated by `pendant.py`; edit the generator, not the mesh.
- `docs/PROPOSAL.md` is the pitch reference; edits there are product decisions, not code cleanup.
- Do not add heavyweight deps to `pipeline/` (no dejavu/MySQL); the pipeline must run on Mathieu's Mac with pip only.
